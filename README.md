# Ledger

A small ledger app: accounts, the debits and credits posted to them, and all-or-nothing bulk import of transactions from CSV. It's a code sample, so the focus is clean structure, careful validation and good tests rather than a long feature list.

**Stack:** Django 6 + Django REST Framework, Vue 3 + TypeScript (Vite), PostgreSQL 17, Docker Compose.

> Work in progress. The full plan is in [plans/PLAN.md](plans/PLAN.md).

## Quick start

Prerequisites: macOS with [Homebrew](https://brew.sh). `make init` installs anything else that's missing: uv, [Volta](https://volta.sh) (Node version manager) and Docker Desktop. If it installs Docker Desktop, it opens it once so you can accept the license.

```sh
make init       # first time only: installs tools, Python 3.13, all dependencies, pre-commit hooks
make db         # start Postgres in Docker
make migrate
```

Then run the two dev servers in separate terminals:

```sh
make backend    # Django API at http://localhost:8001
make frontend   # Vue app at http://localhost:5173
```

Or run the whole stack in Docker with `make up`.

| URL | What |
|---|---|
| http://localhost:5173 | The app |
| http://localhost:8001/api/docs/ | API docs (Redoc) |
| http://localhost:8001/api/schema/ | OpenAPI schema |
| http://localhost:8001/api/health/ | Health check: 200 when the API and database are up |

Ports are chosen to avoid clashing with other local projects: Postgres on **5433** (change `POSTGRES_PORT` and `DATABASE_URL` in `.env`) and the API on **8001** (to change it, pass the same `BACKEND_PORT=...` to both `make backend` and `make frontend`).

## Make targets

| Target | What it does |
|---|---|
| `init` | First-time setup, then `install` |
| `install` | Sync backend and frontend dependencies, install pre-commit hooks. Rerun after pulling |
| `upgrade` | Upgrade backend, frontend and pre-commit hook versions |
| `db` / `up` / `down` | Start Postgres only / start the full stack / stop everything |
| `backend` / `frontend` | Run the Django / Vite dev server locally |
| `migrate`, `makemigrations`, `lint-migrations` | Database migrations |
| `seed` | Load demo accounts and transactions (not built yet: arrives with the `seed_demo` command) |
| `test` | Backend tests (parallel, with coverage) and frontend tests |
| `test-be`, `test-fe` | Backend only / frontend only |
| `test-nc`, `test-serial`, `test-new-db` | Backend tests without coverage / without parallelism / with a fresh test database |
| `lint` | Run every pre-commit hook on every file |
| `api-types` | Export the OpenAPI schema and regenerate the frontend's TypeScript types |
| `clean-coverage` | Delete coverage data files |

```

  config/          settings, URLs, API docs config (openapi.py)
  core/            shared code other apps build on: error handling, API schema defaults
  health/          health check endpoint (the smallest example of the view → service pattern)
  openapi.yml      exported API schema (generated by `make api-types`)
frontend/
  src/api/         typed API client; schema.d.ts is generated from openapi.yml
  src/
plans/             project plan
Makefile           one entry point for both halves
```

## Architecture

**Backend requests flow view → service → serializer.** Views are thin: they validate input with a serializer, call a service function, and return the result. Business logic lives in each app's `services.py` and knows nothing about HTTP.

**Errors have one shape.** Services raise `ApiError` (400) or `ConflictError` (409) from `core.exceptions`. The exception handler turns those, DRF's own errors and anything unexpected into the same response, and logs it (4xx as warnings, 5xx as errors with the traceback):

```json
{"error": {"type": "VALIDATION_ERROR", "message": "Invalid request data.", "fields": {"amount": ["..."]}}}
```

Unexpected errors become a generic 500; their details stay in the log. The API docs list the standard error responses on every endpoint automatically.

**The frontend's types come from the backend.** `make api-types` exports the OpenAPI schema and generates TypeScript types from it. Contract changes show up as a diff in `openapi.yml`, and type errors show up in the frontend.

Code conventions for both halves are in [CLAUDE.md](CLAUDE.md).

## Tooling

- **Python:** [uv](https://docs.astral.sh/uv/) manages Python 3.13, the virtualenv and the lockfile. Make targets run everything through `uv run`, so there's nothing to activate.
- **Node:** Volta pins the Node version in `frontend/package.json`.
- **Tests:** pytest-django with pytest-xdist and pytest-cov for the backend, Vitest and Vue Test Utils for the frontend.
- **Lint and format:** ruff for Python (linting, formatting and import sorting), ESLint, Prettier and a `vue-tsc` type check for the frontend, all run by pre-commit on every commit.
- **API types:** the frontend's TypeScript types are generated from the backend's OpenAPI schema with `openapi-typescript`.
